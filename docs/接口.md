# 脑接口

脑对外的全部能力都在一个 HTTP 面上：JSON 请求 + SSE 事件流；会话实时面另外提供一条**会话级 WebSocket**，答复也在带内上行。平台用它驱动会话，任何其他调用方也可以直接接入。

- 基础地址：`http://<host>:8080`（`config.yaml` 的 `http.port`）
- 路由前缀：`/brain/v1`
- 请求、响应都是 JSON；事件流是 Server-Sent Events
- 会话实时面首选 `GET /brain/v1/session/socket`（Upgrade）；同一份帧集保留了 SSE 载体 `GET /brain/v1/sessions/{id}/stream` 作为回退
- 脑不认识租户。用户身份由请求头声明，归属由共享数据库里的 `dsh_sessions` 判定

实现位置：`packages/dsh-platform-api`。本文以代码为准。

## 1. 认证与公共约定

### 请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `x-app-id` | 是 | 调用方标识，与部署里的 `platform.appKey` 成对配置 |
| `x-app-key` | 是 | 调用方密钥，至少 16 字符 |
| `x-dsh-user-id` | 是 | 这次请求代表哪个用户；`requireUser: false` 时可省略 |
| `x-request-id` | 否 | 幂等与追踪 id；缺省时自动生成并在响应里回显 |

认证失败统一返回 `401`，`code` 为 `unauthorized`；缺少用户头时 `code` 为 `user-required`。未知 `appId` 与错误密钥不给不同提示，调用方无法枚举有效 `appId`。

### 错误响应

所有错误都是同一个形状：

```json
{ "error": { "code": "invalid-cwd", "message": "cwd must be an absolute path" } }
```

常见 `code` 见第 12 节。未预期的内部错误只回 `{"code":"internal","message":"internal error"}`，细节只进脑日志。

### JSON 请求体

- 上限 1 MiB，超出返回 `413 body-too-large`
- 空 body 返回 `400 body-required`；不是合法 JSON 返回 `400 invalid-json`

## 2. 会话模型

```
创建/接续 POST /brain/v1/sessions
    ├── 发消息   POST /brain/v1/sessions/{id}/messages
    ├── 取消     POST /brain/v1/sessions/{id}/cancel
    ├── 实时面   GET  /brain/v1/session/socket                  （WebSocket，首选）
    ├── 实时面   GET  /brain/v1/sessions/{id}/stream            （SSE，回退）
    ├── 看事件   GET  /brain/v1/sessions/{id}/events?after=N      （SSE）
    └── 其余会话操作（模型、命令、目标、后台任务、工作区文件）
```

关键语义：

- **会话不是创建时就存在于内存里的。** `create` 负责新建或从数据库恢复 Agent。除 `create` 外的会话路由只作用于**当前副本上活着的** Agent，否则返回 `404 session-not-found`。
- 脑重启后，平台用同一个 `sessionId` 再调一次 `create`，就会读日志、收束中断的轮次并重新接上。
- 同一个 `sessionId` 的并发 `create` 会合并成一次加载；另一个副本持有写租约时返回 `409 session-busy`，过期后重试即可。
- `messages` 的重复 `requestId` 不会重复入队，仍返回 `202`。

## 4. POST /brain/v1/sessions

新建会话；`sessionId` 已存在时恢复它。

### 额外的请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `x-dsh-model-key` | 是 | 模型密钥。只放在这条会话的内存里，不落盘 |
| `x-dsh-model-base-url` | 是 | 模型接口地址，必须是绝对 `http` / `https` URL；尾部斜杠会被去掉 |
| `x-dsh-model-id` | 否 | 首次使用的模型名；带上时会在这条会话里选中它 |
| `x-dsh-e2b-api-key` | 否 | 同时提供 `x-dsh-e2b-api-url` 和 `x-dsh-e2b-template` 时，写入全局沙箱配置 |
| `x-dsh-e2b-api-url` | 否 | 同上 |
| `x-dsh-e2b-domain` | 否 | E2B 数据面域名 |
| `x-dsh-e2b-template` | 否 | 沙箱模板 |
| `x-dsh-e2b-role-arn` | 否 | 沙箱执行角色 |
| `x-dsh-oss-bucket` | 否 | 工作区卷所在 bucket |
| `x-dsh-oss-endpoint` | 否 | OSS 接入地址 |
| `x-dsh-oss-region` | 否 | OSS 地域 |
| `x-dsh-oss-access-key-id` | 否 | OSS 访问密钥 |
| `x-dsh-oss-access-key-secret` | 否 | OSS 访问密钥 |
| `x-dsh-image-base-url` | 否 | 图片生成接口地址 |
| `x-dsh-image-models` | 否 | 逗号分隔的图片模型名 |
| `x-dsh-image-default-model` | 否 | 默认图片模型 |
| `x-dsh-image-output-dir` | 否 | 图片输出目录 |

模型密钥与接口地址是**每次创建/恢复都要带**的。平台在每次打开会话时都会重新下发；脑不保存全局密钥。

### 请求体

```json
{
  "cwd": "/desk/ws-1",
  "preset": "optional-agent-preset-id",
  "sessionId": "optional-existing-session-id"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `cwd` | 是 | 会话工作目录，绝对路径。进入沙箱时就是工作区挂载点 `/desk`（所有工作区共用，彼此靠独占沙箱隔离） |
| `preset` | 否 | Agent 预设 id；只在新建时使用 |
| `sessionId` | 否 | 复用已有会话；省略时生成 `session-<uuid>` |

### 响应 `201`

```json
{ "sessionId": "session-...", "requestId": "..." }
```

### 错误

| 状态 | code | 场景 |
|---|---|---|
| 400 | `model-key-required` | 缺少 `x-dsh-model-key` |
| 400 | `model-base-url-required` | 缺少或不是合法的 `x-dsh-model-base-url` |
| 400 | `invalid-cwd` | `cwd` 不是绝对路径 |
| 401 | `unauthorized` / `user-required` | 调用方或用户未通过 |
| 409 | `session-busy` | 另一个副本持有这条会话的写租约 |
| 500 | `model-not-configured` | 部署没有默认模型 |

## 5. 提交与中断

### POST /brain/v1/sessions/{id}/messages

```json
{ "text": "帮我看看这个目录", "mode": "queue" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 用户消息正文；空串 `400 invalid-text` |
| `mode` | 否 | `queue`（默认）排到下一回合（`agent.followup`）；`steer` 并入当前回合的下一个 step 边界（`agent.steer`）；其它值 `400 invalid-mode` |

`queue` 和 `steer` 不是同一个动作的两种写法：`queue` 在当前回合结束后才开始新回合，
`steer` 立即影响正在跑的回合。

- 成功返回 `202 { "accepted": true, "requestId": "..." }`
- 消息进入队列后立即返回；模型输出通过 `events` 观察
- 同一个 `requestId` 重复提交不会重复入队
- 会话不在本副本：`404 session-not-found`
- Agent 拒绝接收：`409 prompt-rejected`

### POST /brain/v1/sessions/{id}/fork

从已提交的会话日志分叉出一条新会话。日志只存在于脑里，所以分叉在脑完成。

```json
{ "atSeq": 12 }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `atSeq` | 否 | 分叉点：复制到哪个 `seq`（含）；省略时用最后一个完整的回合边界 |

成功返回 `201 { "sessionId": "session-...", "requestId": "..." }`。新会话由脑生成新的 `sessionId`。

| 状态 | code | 场景 |
|---|---|---|
| 400 | `invalid-at-seq` | `atSeq` 不是非负整数 |
| 404 | `session-not-found` | 源会话不存在或取不到日志 |
| 409 | `fork-unavailable` | 该会话不能分叉 |
| 409 | `fork-migration-required` | 老格式日志需要先迁移 |
| 501 | `not-supported` | 该部署没有组合分叉能力 |

### POST /brain/v1/sessions/{id}/cancel

中断当前轮次，队列里的下一条输入保留。

```json
{ "cancelled": true, "requestId": "..." }
```

状态 `202`。会话不在本副本：`404 session-not-found`。

### POST /brain/v1/sessions/{id}/force-cancel

取消之后轮次仍未收束时的最后手段：向日志补写未完成的工具结果与轮次结束事件，并换掉写租约代际。

```json
{ "forceClosed": true, "events": 3, "requestId": "..." }
```

状态 `202`。没有打开的轮次时 `forceClosed` 为 `false`、`events` 为 `0`。

## 6. GET /brain/v1/sessions/{id}/events

已提交事件回放，然后持续推送实时帧。

### 查询参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `after` | `-1` | 从哪个 `seq` 之后开始回放；`-1` 表示从头 |

`after` 必须是大于等于 `-1` 的整数，否则 `400 invalid-after`。会话不在本副本返回 `404 session-not-found`。

### 帧顺序

```text
: connected                         建立连接
event: snapshot  { cursor }         历史末尾的 seq；-1 表示空日志
event: event     { seq, type, data } 回放，最多 pageSize 条（默认 200）
event: ready     { replayed, after }  回放结束，之后是实时帧
event: event     { seq, type, data } 新提交的事件
event: assistant <原始分片>           模型正在输出的文字，进程内，不落盘
event: status    { status }          驱动状态
event: inbox     { phase }           inserted / claimed / discarded
: keepalive                          默认每 15 秒一行注释
```

- `snapshot` 先到，客户端据此知道历史到哪里结束
- 回放与实时订阅之间不会漏事件；回放覆盖的 `seq` 不会重复推送
- `assistant` 帧是逐字输出；结束时落盘的是完整消息
- 已经写完的历史建议平台直接查库投影，不要依赖这条连接

常见已提交事件类型：`permission/preset`、`sandbox/mode`、`approval/policy`、`model/selection`、`agent/inbox/spliced`、`turn/start`、`step/start`、`system/message`、`user/message`、`request/header`、`request/context`、`assistant/message`、`tool/call`、`tool/result`、`turn/end`。

## 6.1 会话实时面：GET /brain/v1/session/socket 与 GET /brain/v1/sessions/{id}/stream

平台驱动会话 UI 的实时通道。一条连接只服务一个会话，帧集在两种载体上完全相同：

- **首选**：`GET /brain/v1/session/socket`（WebSocket Upgrade），答复在带内上行。
  答复和下行落在同一条连接上，因此一定到达同一条会话的脑进程。
- **回退**：`GET /brain/v1/sessions/{id}/stream`（SSE）+ `POST …/answers`（REST）。
  Upgrade 建不起来（入口不转发、旧版本平台）时使用；两端实现都保留。

### GET /brain/v1/session/socket

Upgrade 请求与普通请求带同一组认证头（`x-app-id` / `x-app-key` / `x-dsh-user-id`），
会话由 **`sessionid` 请求头**指定：宿主 webserver 的 Upgrade 路由按精确路径匹配，
不能把会话 id 放进路径。

握手前就会拒绝，不会升级成 socket：

| 状态 | `code` | 说明 |
|---|---|---|
| 401 | `unauthorized` | 调用方认证失败 |
| 401 | `user-required` | `requireUser` 打开但缺 `x-dsh-user-id` |
| 400 | `session/id-invalid` | 缺 `sessionid` 头或为空 |
| 404 | `session-not-found` | 会话不存在、不属于该用户，或不在本副本 |

**下行**：每条消息一个 JSON，与 SSE 的 `data:` 帧逐字段一致：

```text
{"type":"ready","sessionId":"sess-a","seq":41}
{"type":"event","seq":42,"event":{"type":"user",...}}
{"type":"status","running":true}
{"type":"stream","frame":{...}}
{"type":"waterfall","requestId":"r1","kind":"approval","request":{...}}
{"type":"cancel","requestId":"r1"}
```

| `type` | 字段 | 说明 |
|---|---|---|
| `ready` | `sessionId`、`seq` | 首帧；`seq` 是当前日志偏移 |
| `event` | `seq`、`event` | 已提交的会话日志事件（仅实时，不回放） |
| `status` | `running` | Agent 运行状态 |
| `stream` | `frame` | Assistant 流式分片 |
| `waterfall` | `requestId`、`kind`、`request` | `kind`: `approval` \| `questions` \| `plan` |
| `cancel` | `requestId` | 该请求已撤回或已结算 |

- `ready` 之后先下发一帧当前驱动状态 `status`，再按顺序重放当前所有**未答复**的
  waterfall（重连补投），然后进入实时帧。
- 心跳是 WebSocket `ping`/`pong`，间隔 15 秒；连续错过 pong 的连接会被服务端终止。
- 事件不回放：断线重连后由调用方用 `GET /projections` / `GET /events` 回填。
- 没有订阅者时，waterfall 不认领，交回原链（fail closed）。

**上行**：只接受答复，其他消息忽略。

```json
{ "type": "answer", "requestId": "r1", "outcome": { "kind": "result", "value": "approved" } }
```

| 回执 | 说明 |
|---|---|
| `{"type":"ack","requestId":"r1"}` | 已结算 |
| `{"type":"answer-error","requestId":"r1","code":"session/mismatch"}` | 请求已撤销、已结算或不属于本会话 |
| `{"type":"answer-error","requestId":"r1","code":"invalid-answer"}` | `outcome` 形状不对 |

上行的消息体上限 256 KiB。非 `answer`、缺 `requestId`、不是合法 JSON 的消息静默忽略。
待答表只在内存里：脑重启即丢，此时回合也随之中止（fail closed）。

### GET /brain/v1/sessions/{id}/stream（回退载体）

响应 `200`，`text/event-stream; charset=utf-8`。事件名固定为 `frame`，`data` 是一个
与上面逐字段相同的 JSON 帧：

```text
: connected
event: frame {"type":"ready","sessionId":"sess-a","seq":41}
event: frame {"type":"event","seq":42,"event":{"type":"user",...}}
event: frame {"type":"status","running":true}
event: frame {"type":"stream","frame":{...}}
event: frame {"type":"waterfall","requestId":"r1","kind":"approval","request":{...}}
event: frame {"type":"cancel","requestId":"r1"}
: keepalive
```

- 帧语义、`ready`→`status`→waterfall 补投的顺序都与 socket 相同。
- 心跳是每 15 秒一行 `: keepalive` 注释；没有 `ping`/`pong` 帧。
- 会话不在本副本：在写出任何 SSE 字节之前返回 `404 session-not-found`。
- 这条载体没有上行通道，答复走下一节的 REST 接口。

### POST /brain/v1/sessions/{id}/answers

```json
{ "requestId": "r1", "outcome": { "kind": "result", "value": "approved" } }
```

- `outcome.kind` 是 `result` 或 `rejected`；`rejected` 可带 `error`
- 成功返回 `200 { "accepted": true }`
- `requestId` 不属于本会话的待答表（未知、已结算、别的会话）：`409 session/mismatch`
- 请求体不是合法 JSON 或形状不对：`400 invalid-json` / `400 invalid-answer`
- 待答表只在内存里：脑重启即丢，此时回合也随之中止（fail closed）
- 与 socket 带内答复共用同一张待答表，重复结算只会得到 `409`（或 `answer-error`）

## 7. 会话内的其他操作

以下接口都要求会话在本副本上活着，否则 `404 session-not-found`；未组合的服务返回 `501 not-supported`。

### POST /brain/v1/sessions/{id}/model

```json
{ "model": "deepseek-chat", "provider": "user", "reasoningEffort": "medium" }
```

- `model` 也可以用 `modelId`
- 省略 `provider` 时默认为 `user`
- 只影响这条会话之后的轮次
- 成功返回 `{ "selected": { "provider": "...", "model": "..." } }`
- 模型解析失败：`400 model-unavailable`

### GET / POST /brain/v1/sessions/{id}/commands

- `GET` 返回 `{ "items": [ ... ] }`
- `POST { "line": "/compact" }` 返回 `{ "result": ... }`
- 空 `line`：`400 invalid-line`

### GET / PUT /brain/v1/sessions/{id}/goal

- `GET` 返回 `{ "goal": ... | null }`
- `PUT` 的 body 原样交给目标服务，做整值修改
- 没有目标：`404 goal-not-found`

### POST /brain/v1/sessions/{id}/goal/{action}

`action` 只能是 `pause`、`resume`、`complete`、`clear`，否则 `404 not-found`。

### POST /brain/v1/sessions/{id}/preset

```json
{ "agentPreset": "preset-id" }
```

返回 `{ "agentPreset": "..." }`；缺少字段 `400 invalid-preset`。

### GET / POST / DELETE /brain/v1/sessions/{id}/message-feedback

- `GET` 返回该会话的反馈列表
- `POST` / `DELETE` 的 body 原样交给反馈服务

### POST /brain/v1/sessions/{id}/feedback

会话级备注，body 原样交给反馈服务。

### GET /brain/v1/sessions/{id}/projections

返回 `{ "projections": ... }`。

## 8. 后台任务

任务进程在沙箱里，任务编号在脑内存里。脑重启后旧编号失效，会话重新发起即可。

### GET /brain/v1/sessions/{id}/jobs

SSE。每次生命周期变化都推送**完整清单**：

```text
event: rows { "type": "rows", "jobs": [ ... ] }
```

### GET /brain/v1/sessions/{id}/jobs/{jobId}/output?from=N

SSE。`from` 是字节偏移，>= 0；不传时从最早保留的输出开始。

```text
event: opened { "type": "opened", "job": {...}, "from": 0 }
event: output { "type": "output", "chunks": [...], "next": 1024 }
event: output { "type": "output", "chunks": [...], "next": 2048, "lossy": true }
event: status { "type": "status", "job": {...} }
```

`lossy: true` 表示更早的输出已因缓冲上限被丢弃。任务结束或不可见：`404 job-not-found`。

### POST /brain/v1/sessions/{id}/jobs/{jobId}/kill

```json
{ "outcome": "requested" }
```

`outcome` 也可能是 `already-finished`。未知任务：`404 job-not-found`。

## 9. 工作区文件

给侧边栏文件树用。路径只能落在会话所在工作区的沙箱根目录里。

### 路径规则

- 根目录来自沙箱绑定（工作区挂载点 `/desk`）
- 接受三种写法：
  - 别名 `/workspace-{workspaceId}` 及其子路径
  - 相对路径，从工作区根解析
  - 工作区内的绝对路径
- 越出工作区、或路径上任何一段是符号链接：`403 workspace-file/outside-workspace`
- 工作区 id 先读 `x-dsh-workspace-id` 请求头，缺省时查会话目录

### GET /brain/v1/sessions/{id}/workspace-files?path=...

列目录。`path` 省略时列工作区根。

```json
{
  "path": "src",
  "entries": [{ "name": "main.ts", "type": "file", "size": 1024 }],
  "truncated": false
}
```

最多返回 1000 个直接子项，`truncated` 表示被截断。目录不存在：`404 workspace-file/not-found`；不是目录：`400 workspace-file/not-directory`。

### GET /brain/v1/sessions/{id}/workspace-files/content

文本（默认）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `path` | 必填 | 文件路径 |
| `offset` | `1` | 起始行号，1 起 |
| `limit` | `400` | 行数，最大 2000 |
| `baseFile` | 无 | 当 `path` 是相对路径时，相对这个文件所在目录解析 |

```json
{
  "absolutePath": "/workspace-ws-1/README.md",
  "version": "1234:1760000000000",
  "bytes": 1234,
  "offset": 1,
  "text": "...",
  "lines": 42,
  "eof": true
}
```

二进制（`bytes=1`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `offset` | `0` | 字节偏移 |
| `length` | 到文件末尾 | 读取字节数 |

```json
{
  "absolutePath": "/workspace-ws-1/logo.png",
  "version": "...",
  "bytes": 2048,
  "offset": 0,
  "data": "iVBORw0KGgo...",
  "eof": false
}
```

上限：文本 8 MiB，二进制 16 MiB，超出 `413 workspace-file/too-large`；二进制文件按文本读 `415 workspace-file/not-text`；不是普通文件 `400 workspace-file/not-regular-file`。

### GET /brain/v1/sessions/{id}/workspace-files/stat?path=...

```json
{ "absolutePath": "...", "version": "...", "bytes": 1024 }
```

`bytes` 只对普通文件返回。

### POST /brain/v1/sessions/{id}/workspace-files/upload?path=...&name=...

- `path`：目标目录，省略时为工作区根
- `name`：单个路径段，不能含 `/`、`\`、`..`
- body：原始字节，上限 64 MiB

```json
{ "name": "a.txt", "path": "/workspace-ws-1/a.txt", "bytes": 3 }
```

## 11. 单独接入

脑不跑平台时，调用方要自己维护目录表。归属校验读 `dsh_sessions`，沙箱路由读 `dsh_sessions`、`dsh_workspaces`、`dsh_users`，技能和 MCP 读 `dsh_skills`、`dsh_mcp_servers`，以及工作区的选择表 `dsh_workspace_skills`、`dsh_workspace_mcp_servers`。最小的建表与示例数据：

```sql
CREATE TABLE IF NOT EXISTS dsh_users (
  id text PRIMARY KEY,
  display_name text NOT NULL DEFAULT '',
  password_hash text NOT NULL DEFAULT '',
  role text NOT NULL DEFAULT 'member',
  status text NOT NULL DEFAULT 'active',
  skills_volume text
);

CREATE TABLE IF NOT EXISTS dsh_workspaces (
  id text PRIMARY KEY,
  user_id text NOT NULL,
  name text NOT NULL DEFAULT '',
  host_root text NOT NULL DEFAULT '',
  guest_root text NOT NULL DEFAULT '/desk',
  volume_name text,
  state text NOT NULL DEFAULT 'active',
  -- false：没配置过选择，沿用全部启用；true：下面两张表就是权威列表，允许为空。
  selection_configured boolean NOT NULL DEFAULT false
);

CREATE TABLE IF NOT EXISTS dsh_workspace_skills (
  workspace_id text NOT NULL,
  skill_name text NOT NULL,
  skill_scope text NOT NULL,
  PRIMARY KEY (workspace_id, skill_name, skill_scope)
);

CREATE TABLE IF NOT EXISTS dsh_workspace_mcp_servers (
  workspace_id text NOT NULL,
  server_name text NOT NULL,
  server_scope text NOT NULL,
  PRIMARY KEY (workspace_id, server_name, server_scope)
);

CREATE TABLE IF NOT EXISTS dsh_sessions (
  id text PRIMARY KEY,
  user_id text NOT NULL,
  workspace_id text,
  preset_id text,
  title text,
  status text NOT NULL DEFAULT 'active'
);

CREATE TABLE IF NOT EXISTS dsh_skills (
  user_id text NOT NULL,
  name text NOT NULL,
  description text NOT NULL DEFAULT '',
  scope text NOT NULL DEFAULT 'private',
  enabled boolean NOT NULL DEFAULT true,
  PRIMARY KEY (user_id, name)
);

CREATE TABLE IF NOT EXISTS dsh_mcp_servers (
  user_id text NOT NULL,
  server_name text NOT NULL,
  transport text NOT NULL,
  target text NOT NULL,
  config jsonb,
  enabled boolean NOT NULL DEFAULT true,
  scope text NOT NULL DEFAULT 'private',
  PRIMARY KEY (user_id, server_name)
);

INSERT INTO dsh_users (id) VALUES ('alice') ON CONFLICT DO NOTHING;
INSERT INTO dsh_workspaces (id, user_id) VALUES ('demo', 'alice') ON CONFLICT DO NOTHING;
INSERT INTO dsh_sessions (id, user_id, workspace_id) VALUES ('demo', 'alice', 'demo') ON CONFLICT DO NOTHING;
```

`workspace_id` 必须非空，沙箱按它找卷；`guest_root` 是工作卷在沙箱里的固定挂载点，所有工作区都是 `/desk`。表中的 `workspace_id` 允许为空只为兼容老库，平台在建会话、认领会话和启动回填时都会把空值补到成员的默认工作区。技能和 MCP 的行也可以先不建，留空只是没有可用的技能和服务。

工作区想限定用哪几条技能 / 服务时，把 `selection_configured` 置 `true`，再往 `dsh_workspace_skills`、`dsh_workspace_mcp_servers` 里写 `(名字, 作用域)`；两张表为空表示这个工作区明确一个都不接。保持 `false`（老库升级后的默认值）则沿用这个用户所有已启用的条目。

## 12. 一次最小调用

```bash
BASE=http://127.0.0.1:8080
AUTH=(-H "x-app-id: platform" -H "x-app-key: $APP_KEY" -H "x-dsh-user-id: alice")

# 1. 新建或恢复会话。模型密钥只出现在请求头里。
curl -sS -X POST "$BASE/brain/v1/sessions" \
  "${AUTH[@]}" \
  -H "content-type: application/json" \
  -H "x-dsh-model-key: $MODEL_KEY" \
  -H "x-dsh-model-base-url: https://api.example.com/v1" \
  -H "x-dsh-model-id: deepseek-chat" \
  -d '{"cwd":"/desk/demo","sessionId":"demo"}'

# 2. 先订阅事件流（另开一个终端）
curl -sSN "$BASE/brain/v1/sessions/demo/events?after=-1" "${AUTH[@]}"

# 3. 发一条消息
curl -sS -X POST "$BASE/brain/v1/sessions/demo/messages" \
  "${AUTH[@]}" -H "content-type: application/json" \
  -d '{"text":"你好"}'
```

## 13. 错误码

| code | 状态 | 含义 |
|---|---|---|
| `unauthorized` | 401 | `x-app-id` / `x-app-key` 不对 |
| `user-required` | 401 | 缺少 `x-dsh-user-id` |
| `body-required` / `invalid-json` / `invalid-body` | 400 | 请求体问题 |
| `invalid-answer` | 400 | 答复形状不对 |
| `body-too-large` | 413 | 超过 1 MiB |
| `model-key-required` | 400 | 创建会话缺少模型密钥 |
| `model-base-url-required` | 400 | 创建会话缺少合法模型地址 |
| `invalid-cwd` | 400 | 工作目录不是绝对路径 |
| `invalid-text` | 400 | 消息为空 |
| `invalid-mode` | 400 | `mode` 不是 `queue` / `steer` |
| `invalid-at-seq` | 400 | 分叉点不是非负整数 |
| `fork-unavailable` / `fork-migration-required` | 409 | 会话不能分叉 / 老日志需迁移 |
| `fork-failed` | 500 | 分叉内部失败，细节看脑日志 |
| `session/mismatch` | 409 | 答复的请求不属于该会话（socket 带内为 `answer-error`） |
| `session/id-invalid` | 400 | 会话 socket 的 Upgrade 缺少 `sessionid` 头 |
| `invalid-model` | 400 | 模型选择缺字段 |
| `model-unavailable` | 400 | 模型无法解析 |
| `invalid-line` | 400 | 命令为空 |
| `invalid-preset` | 400 | 缺少 `agentPreset` |
| `invalid-after` / `invalid-from` | 400 | 游标不是合法整数 |
| `session-not-found` | 404 | 会话不存在、不属于调用方，或不在本副本 |
| `session-busy` | 409 | 另一副本持有写租约 |
| `prompt-rejected` | 409 | Agent 拒绝接收消息 |
| `goal-not-found` | 404 | 会话没有目标 |
| `job-not-found` | 404 | 任务不存在或对该会话不可见 |
| `method-not-allowed` | 405 | 方法不对 |
| `not-supported` | 501 | 该部署没有组合这项能力 |
| `workspace-file/not-found` | 404 | 文件或目录不存在 |
| `workspace-file/outside-workspace` | 403 | 路径越界或经过符号链接 |
| `workspace-file/not-directory` / `not-regular-file` | 400 | 类型不对 |
| `workspace-file/too-large` | 413 | 超过预览或上传上限 |
| `workspace-file/not-text` | 415 | 二进制文件按文本读取 |
| `workspace-file/unavailable` | 503 | 沙箱暂时不可用 |
| `internal` | 500 | 未预期错误，细节看脑日志 |
